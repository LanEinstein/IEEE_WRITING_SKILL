# Minimal writing workspace

Agent-filled reference, not a questionnaire. Use a brief response card for a small task. For a new full paper, one project `WRITING_WORKSPACE.md` can hold these blocks. Reuse existing project files; omit unused fields. Do not copy example paths into a real project.

```text
Request / active manuscript / output location:
Target venue, article type, stage: unknown until established
Official requirements: source URL + checked date + scope, or pending
Content profile: journal_method_structured_v2 (journal method papers)
Requested delivery unit: user choice; otherwise subsection
Apply authority: exact user instruction / proposal-only / read-only
Current status: proposed / applied / verified / pending

Thesis: one sentence
Problem → technical change → evidence → claim boundary:
Contributions: actual independent items, with method/evidence locations
Outline: paragraph task + first-sentence message + source/float + next step

Fact ID | Content | Source/version | Metric/protocol | State | Claim boundary
...

Open issues: affected sentence + precise missing/conflicting item + next action
Completed units / pending approval / rejected directions:
Checks: actual command/scope/result or not run + reason
Next authorized step:
```

For full protocols or a complex method, add the relevant [claims/evidence table](claims-evidence.md) or [method mapping](title-figure-symbol-map.md) inside the same file. Do not require a second ledger merely because a template exists. Keep draft placeholders visible and out of a submission-ready manuscript.
