# Independent and cross-model review

Use when the user requests independent or cross-model collaboration, or when delegation is otherwise available and authorized. A serial self-review is useful but must not be presented as an independent agent or another model.

1. Freeze an identifiable candidate version. Give the reviewer the actual task, relevant source artifacts, scope, and evidence boundaries. For usability/skill review, use realistic requests and isolated output workspaces; do not supply the desired answer.
2. Share private material only within the existing authorization. “Collaborate with Claude” authorizes the requested collaboration, not publication or messages to unrelated people. Use the actual available runtime; do not relabel another agent as Claude.
3. Request concrete findings: location, consequence, evidence, proposed fix, and pass condition. Avoid a fixed number of defects or assumed acceptance outcome.
4. Adjudicate each material finding: adopt, modify, reject with evidence, or pending. Review suggestions are not facts; preserve numerical results and the actual method.
5. Recheck the revised candidate against the accepted findings and run realistic tasks when the workflow changed. Report which version and scope were reviewed.
6. If the tool is unavailable, errors, or quota-limited, make useful local progress and state the external review is pending/unavailable. Never claim external agreement from an attempted call or a previous draft's review.
