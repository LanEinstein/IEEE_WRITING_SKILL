# Outline for an evidence-ready paper

Use for a full new manuscript or a structural rewrite. Local section tasks skip this full-paper artifact. Reuse an approved outline; only reopen affected decisions. Honor any explicit outline-review gate, otherwise continue within the draft authorization.

1. **Scope:** active manuscript; target/article type/stage and verified requirements or pending; profile; requested review/apply scope.
2. **Thesis:** one specific technical insight. Draft title expresses task and principle; no arbitrary word limit unless required.
3. **Contribution map:** problem → technical change → method subsection → evidence → boundary. Use real independent contributions, default three for the structured method profile.
4. **Paragraph plan:** every paragraph's single task, topic sentence message, sentence functions, source/float, and transition. Use [sentence-plan.md](sentence-plan.md) for actual A/P/R/M/E/F/C slots, not a generic “background-method-results” list.
5. **Floats:** question answered, data/source status, essential content, reading conventions, insertion point. Identify who prepares the artifact from the user's request; the suite can prepare code-native diagrams/data plots when authorized and tools permit. Do not require the user to draw every figure.
6. **Literature:** nearest work and supporting sources with metadata/content status, not an assumed prestige gate.
7. **Open items:** precise missing fact/conflict, affected claim, next step; continue independent parts.

Typical journal method skeleton: Introduction → Related Work → Method → Experiments → Conclusion. Follow actual journal/type needs for theory, systems, hardware, or application papers; do not impose learning-method ablations or cost studies on unrelated evidence types. Suggested drafting order follows evidence dependencies and user preference, not a mandatory sequence.
